# RemVibe Archive — working rules

- Product First, Functionality First, Windows First. Windows/Linux real acceptance; macOS design compatibility, FreeBSD future target. No unrun PASS.
- Archive owns RVA V3 creation, entry reading, compression, integrity, validation and extraction only. No networking, file transfer orchestration, UI, SFX executable, deployment, customer metadata models or service lifecycle.
- New incompatible .rva format; no NTA V2 reader/converter/adapters. Preserve existing legacy consumers via pinned revisions until coordinated migration. Entire old implementation isolated under _legacy, including historical docs and old Dart workflow (inactive in the new layout). Do not change legacy code.
- Root Cargo library remvibe_archive; later dart/ is remvibe_archive_dart, with private native/ FFI crate remvibe_archive_ffi. No crates/ directory or extra Dart package nesting. Do not scaffold Dart/FFI until ARCHIVE-FFI-01. Rust consumers link directly, no Dart or FFI dependency; prefer pure Rust dependencies and self-contained distribution.
- Manifest-last, independently compressed payloads, zlib/none, SHA-256, region-relative offsets, bounded Read+Seek and entry streaming; selected entries, regular files/directories and empty entries. Real progress and cancellation. First profile unencrypted and without symbolic links/junctions/special entries; explicitly reject rather than follow/skip. Encryption and link support require separate scope approval; do not silently change the profile.
- FileSystem Core is the shared authority for native metadata, permissions and filesystem algorithms. Pin an accepted FileSystem revision when integrating. Preserve lossless native names, supported timestamps, permissions, ordered Windows DACL/opaque ACE and attributes when requested; cheap stat vs explicit full metadata capture, selective MetadataPolicy/results. No guessed foreign ownership/ACL or automatic privileged mode restoration. Direct and archived transfer share policy; do not duplicate OS algorithms.
- Bounds, path/collision validation, strict integrity and absent-destination sibling staging; no merge/overwrite, source deletion, archive append/edit/compact or transfer finalization in current checkpoint. Report cleanup failures; no unnecessary hardening.
- Implement approved checkpoints only. Direct Git repository work, no patches, copies, extra worktrees, speculative scaffolding, UI automation or unrelated test/CI changes. Preserve unrelated changes. Focused validation. Explicit approval before next checkpoint and merge.
- Future deployment/SFX requirements are recorded in https://github.com/nusretm/remvibe_deployment. They do not change the active roadmap. Installer/Updater evaluation is separate after Archive FFI and before coordinated migration.
