# remvibe_archive

Native Rust archive library for the new RVA V3 (.rva) format. Direct Cargo dependency for Rust consumers, including future File Transfer, Deployment and SFX. No backward compatibility with NTA V2.

## Layout

- Cargo.toml, src/, examples/: independent Rust library named remvibe_archive.
- dart/: remvibe_archive_dart package (ARCHIVE-FFI-01 accepted and closed); its native/ directory contains the private Rust FFI crate remvibe_archive_ffi, not a separate product.
- docs/: current format and continuity documentation.
- _legacy/: exact pre-redesign repository snapshot, including historical Dart/C++ implementation, docs, examples and retired workflow. Not part of the new build. Legacy consumers continue using their pinned commits until coordinated migration.

## Writer (Checkpoint B)

Use absolute source/destination paths and explicit relative ArchivePath values. ArchiveWriter::new, add_file, add_file_with_compression, add_directory (recursive or entry only), finish or abort. WriterOptions defaults to Zstd level 3 for files and manifest (Zlib level 6 and None supported), 1 MiB buffer and basic FileSystem metadata; full metadata is opt-in. Progress callback and thread-safe CancellationToken are available. Output is published only at finish, without replacing a destination. Any add/finish error aborts staging. Run cargo run --example writer_probe for focused acceptance.

## Reader (Checkpoint C)

ArchiveReader::open(path, ReaderOptions), open_region(path, offset, length, options), from_reader(Read+Seek, options), from_region(source, offset, length, options). List via entries()/manifest(); read_entry_to(index, &mut Write) streams provisional bytes until success, verify() verifies all payloads, extract_to(absent directory, ExtractOptions) or extract_entry_to(index, absent filename, options) publishes only verified output. Shared MetadataPolicy default; None defers metadata. ReaderOptions controls manifest limits, buffer and cancellation. Run cargo run --locked --example reader_probe.

## Checkpoint F — Split Archive (accepted and closed)

`WriterOptions { layout: ArchiveLayout::Split { max_part_size }, ..Default::default() }` writes a logical RVA directly into physical parts, without an intermediate complete archive. The destination is an absent directory (for example backup.rva.parts), containing part.000001, part.000002, etc. Each physical limit includes a 72-byte part envelope. The entire private sibling staging directory is published by one no-replace rename. `WriterResult.archive_bytes` is logical RVA length; `part_count` and `physical_bytes` report actual volume count and total bytes. Default Single behavior unchanged. Open with `ArchiveReader::open_split(directory, ReaderOptions::default())`; same manifest, entry reading, verify and extraction APIs. `SplitReader` implements Read + Seek and validates complete set identity, numbering and sizes without concatenating. Run `cargo run --locked --example split_probe` for local acceptance; `-- produce <absent-directory>` / `-- consume <directory> <other-os>` for real bidirectional exchange. ### Writer API (B)
Use ArchiveService.instance.createWriter(ArchiveNativePath.fromString(absoluteDestination), options: ArchiveWriterOptions(...)).result. Await each writer.addFile(source: ..., path: ..., compression: ...).result or writer.addDirectory(source: ..., path: ..., recursive: true).result; writer.finish().result publishes an absent destination; writer.abort().result discards staging; always await writer.close() in finally. Single default; ArchiveLayout.split(BigInt maxPartSize) for split directory. Subscribe to operation.progress immediately for Core snapshots and call operation.cancel() to request cancellation; always await result. ArchivePath.fromString uses slash-separated relative names; raw native filename units use explicit ArchivePathComponent.unixBytes/windowsUtf16 and ArchiveNativePath units. A failed/cancelled Core add closes the writer; no overwrite or resume. Windows/Linux runtime acceptance completed. Use dart/example/writer.dart with the direct Rust example dart/native/examples/writer_verify.rs as documented in continuity. See Reader API below.

### Reader API (C)
Use ArchiveService.instance.openReader(ArchiveNativePath.fromString(absoluteSource), source: ArchiveSource.single()).result. ArchiveSource.split() selects a split directory; ArchiveSource.embedded(offset: BigInt, length: BigInt) selects a bounded host file region. Await reader.manifest().result (immutable typed entries and FS-compatible metadata), reader.verify().result (payload integrity), reader.extractTo(destination, options: ArchiveExtractOptions(...)).result or reader.extractEntryTo(index, destination, options: ...).result. Use ArchiveExtractOptions(metadataPolicy: null) to defer all metadata application; default policy restores supported modified time and POSIX mode, without implicit privileged mode or foreign ownership/ACL. ExtractionSync.buffered default, perFile explicit. Subscribe to progress for operation-local outputBytes/totalBytes; processedBytes works for both writer and reader. Always await operation.result after cancel; cancelled Reader must close/reopen. Always await reader.close() in finally. Source must remain immutable. C Windows/Linux acceptance completed. Binary entry stream is available in D (accepted). See continuity for Rust fixture and Dart Reader probe commands.

### Selected entry streaming (D)
Call reader.readEntry(entry.index) to obtain ArchiveReadOperation. Consume its single-subscription stream (Stream<Uint8List>) with await for or a subscription that pauses during asynchronous consumption. Then await operation.result for verified length/SHA-256 and counters; stream closure alone does not imply success. Data chunks are provisional until successful result, discard on error. Cancel through operation.cancel(), subscription cancellation, or reader.close(); always await result and close Reader, reopen after cancellation. A nonempty stream must be consumed or cancelled; result alone is not a drain. Native raw chunks up to 256 KiB, one outstanding acknowledgement/credit, bounded bridge buffering and TransferableTypedData across the receiver isolate. Existing Core read_entry_to performs decompression and verification; no JSON/base64 payload or full-file buffering. Windows/Linux runtime acceptance completed; use dart/example/streaming.dart with existing reader_probe fixtures. Final clean native hook and bundled distribution technical acceptance completed in E.
