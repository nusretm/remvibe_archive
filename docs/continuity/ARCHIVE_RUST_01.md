## Checkpoint B implementation — 2026-11-25

ArchiveWriter source committed: single sibling create_new staging file, header, per-entry streaming payloads (flate2 rust_backend Zlib / None; default level 6), streaming SHA-256, manifest/footer, sync and publication via FileSystemService.rename. Explicit paths, recursion or directory entry only, empty files/dirs, basic/full metadata capture. Progress reports actual source bytes and entry completion; no guessed total for incrementally added entries. Cancellation checked between chunks and before publication; successful publication wins. Add/finish errors close writer and attempt cleanup; explicit abort reports cleanup failures, Drop best effort. Uses 1 MiB default buffer configurable up to 64 MiB. Absolute caller-selected paths required; final source entries and recursive children reject links/reparse/special types. Caller-selected parent aliases may resolve normally; checks are not a snapshot or race-proof traversal against concurrent hostile source changes. Size/mtime/byte count checks detect ordinary changes, not all same-size/same-mtime replacement. Destination-inside-recursive-source rejected, staging must not be archived. Shared FileSystem public rename handles native no-replace; no new platform mutation algorithms. Full metadata capture opt-in, not automatic restoration. No ArchiveReader, FFI, deployment, transfer or CI work.

## Checkpoint C implementation — 2026-11-25

Generic ArchiveReader<R: Read+Seek> owns source; File open/open_region, from_reader/from_region for memory and custom sources. Validated envelope/manifest on open, bounded regions, configurable buffers and limits. read_entry_to streams into caller sink (provisional until success; discard on failure); verify validates all streams; extraction validates all selected bytes and hashes before publication, no redundant verification pass. Zlib low-level decoder requires StreamEnd, exact stored input consumption and exact output size; reject trailing, truncated and oversized payload. Reader progress real output bytes, selected total known, cancellation at chunks and before publication. Same token type as writer, fresh token for new operation after cancellation. Caller must keep source immutable. Hashes are integrity, not publisher authentication.

Extract to an absent directory or one regular file at explicit absent filename. Single sibling stage; build exclusive native target tree before payload writes, case/normalization aliases detected by actual create_new/create_dir, explicit Windows device/trailing-dot/space checks during native conversion. Implicit parents allowed; no archive link entries. Metadata applied through FileSystemService after payload verification; files then deepest explicit directories; default policy preserves supported modified time/mode, opt-in other fields, None defers metadata. Report per-entry results at application time; explicit Windows ACL inheritance may change child results later; no final inherited ACL exactness claim. Failed required metadata blocks publication. Cleanup uses shared FileSystem methods to recover staged directory access/readonly where possible and delete; foreign owner/ACL can prevent cleanup, report retained stage with error. No platform permission algorithms duplicated. Caller-selected parent is trusted; no adversarial concurrent path mutation guarantee. No overwrite/merge, source deletion, directory subtree selection, FFI or deployment. No dependency additions; A/B Cargo.lock unchanged.

Focused reader_probe covers writer-generated archive, file/memory/embedded region, streaming entry, verify, full and single-file extraction, implicit/empty dirs, timestamps/mode, progress, corruption, exact zlib bounds, cancellation, destination conflict, required metadata failure and actual target case aliases.
